# 0076: Pen latency: every pen sample, fast ink, HTTPS on the LAN

Status: accepted (INK-181). Tablet check pending (see the last section).

## Context

The owner reported that writing on the tablet lags more and more while writing, so the hand cannot see the ink it is making, and that panning is slow for about a second after a canvas opens. INK-174 (decision 0073) cut the app's own per-frame work but could not reproduce the lag headless.

What the measurements showed:
- **The app gets one pen point per frame.** In the owner's saved strokes the median gap between points is 10 to 12 px. Matched against the device log (decision 0059), a stroke has 1.0 point per drawn frame, about 79 points a second, from a stylus that samples at about 240 Hz. Two things cause it. Browsers deliver at most one `pointermove` per frame and keep the rest in `getCoalescedEvents()`, which they expose only in a secure context, and `http://<laptop-ip>` is not one. Excalidraw 0.18.1 also wraps its move handler in `throttleRAF` (one call per frame, last event only) and never reads coalesced events. Every frame then costs latency and shape: curves come out as straight segments.
- **Excalidraw draws the stroke 1.5 frames after the event**, measured headless: the move is handled in the next animation frame, React commits, and with `EXCALIDRAW_THROTTLE_RENDER` the new-element canvas is drawn one frame later again.
- **A tablet A/B on a copy of the owner's `default` canvas** (same Android tablet and browser, 120 and more strokes each, the stock Excalidraw perf page against the app) shows the app equal to stock. While writing: 82 against 84 fps, 1.2 against 0.7 percent of frames over 34 ms, 70 pen events a second on both, median event age 10 against 9 ms. Neither slowed down over the session (stock 72 to 82 fps, app 79 to 79). Finger pan: 45 against 43 fps, both with long frames, and about 20 main-thread pauses of 200 ms or more on both. The lag is Excalidraw's pipeline on this browser, not the shell.
- The laptop's Wi-Fi is weak (-79 dBm on 2.4 GHz, 5.5 Mbit/s receive, tablet ping 13 to 323 ms). That explains saves of 4 to 15 s and crop uploads of 11 s, not the ink lag: ink is drawn locally.
- tldraw reads coalesced events in its draw tool (since v3.12), but it would hit the same secure-context wall on LAN HTTP, it still draws a frame late, and moving would rewrite the chunker, hashes, ops and export, which are built on Excalidraw elements. It also needs a license key in production. Not taken.

## Decision

- **Every pen sample.** `web/src/ink/penSamples.ts` collects every coalesced sample per pointer in a window capture listener. That listener runs before Excalidraw's own, so this event's samples are in by the time Excalidraw's throttled handler reads the hook. It publishes `globalThis.__inkbridgePenSamples`. The Excalidraw patch (`web/patches`, dev and prod builds, next to the INK-062 pen-feel numbers) makes the freedraw move handler add every collected sample since the last frame, with the same repeated-point rule and real pressures. The pointerup handler drains what arrived after the last frame before it adds the final point. Without the hook (the stock perf page, a test) both fall back to their own event, so Excalidraw behaves as before. Headless with four coalesced samples per frame, 160 samples give 162 points against 42 for stock.
- **Fast ink.** `web/src/ink/fastInk.ts` draws the stroke in progress on its own canvas (`FastInk.tsx`, `position: fixed` over Excalidraw's, `pointer-events: none`, `desynchronized` where supported). It draws inside the `pointermove` handler itself and does not wait for a frame. It uses the same `perfect-freehand` version as Excalidraw (1.2.0, now a direct dependency) with the patched options (a test reads them from the Excalidraw build), the same points, plus the samples Excalidraw has not taken yet, and the same path construction. Mid-stroke, 99.7 percent of ink pixels agree with Excalidraw's own canvas. It draws only an opaque, unrotated stroke: the highlighter (35 percent opacity) would show darker where both layers overlap, so it keeps Excalidraw's timing. It follows the pointer that went down on the Excalidraw canvas (pen and mouse, a finger only with Finger draws on), so palm touches never draw. It is cleared once Excalidraw has finalised the stroke and two more frames have passed, so the finished stroke is never missing. Each move clears and paints only the stroke's box. Measured headless: ink at the pen tip in 0 frames instead of 1.5. Main-thread cost at 6x throttle is 29.0 against 28.4 ms per move with the layer off, within noise.
- **HTTPS on the LAN.** `make serve-https` runs `scripts/lan-cert.sh`, which makes a private CA once and a server certificate for this machine's LAN addresses in `data/tls/` (gitignored). It is re-run on each start and makes a new server certificate when the IP changes. Then it serves the built app over TLS on port 4173 (the laptop firewall lets the LAN reach 4173 and 5173 only), with `INKBRIDGE_PUBLIC_URL` set to that origin. `make serve` (HTTP on 8000) is unchanged. The WebSocket already follows the page's scheme (`wss`). Checked headless at `https://<LAN IP>`: a secure context, the socket connects, a save stores 162 points and 162 pressures for one stroke.
- **Measurement.** The device log's `input.<pointerType>` record per stroke carries `moves`, event age `age_p50/p95/max`, `samples` (coalesced samples) and `secure`. A `page.<name>` record says which page wrote the lines that follow. The stock perf page writes the same log, so a tablet A/B compares like with like. Perf switches: `off:fastink` and `off:throttle` (render throttle off); the stock page takes `?throttle=0`.
- Not changed: `EXCALIDRAW_THROTTLE_RENDER` stays on, since the fast ink covers its frame. Pressures and `simulatePressure` keep their flow: a test pins `element.pressures[i]`, and a saved stroke has as many pressures as points. Drafts, hashes and saves are untouched.

## Consequences

- The tablet must open the HTTPS address to get the extra samples. Over plain HTTP the fast ink still removes Excalidraw's 1.5 frames, but points stay at one per frame.
- An Excalidraw upgrade must carry the move and pointerup hunks of the patch over. `penFeel.test.ts` fails if the hook disappears from either build or from the patch file.
- The fast ink duplicates Excalidraw's stroke drawing for the stroke in progress. If Excalidraw's freedraw options or path code change, `fastInk.test.ts` fails on the options. The path construction is copied, not shared.
- Not addressed: finger panning (about 45 fps on stock as well, Excalidraw redraws the static scene every pan frame) and the 200 ms or longer pauses seen on stock too. They need their own work.

Pending, for the owner.
1. Trust the CA once. Copy `data/tls/inkbridge-ca.crt` to the tablet (LocalSend works: the firewall allows it), then Settings > Security > Encryption & credentials > Install a certificate > CA certificate. Firefox for Android also needs Settings > About Firefox (tap the logo five times) > Secret settings > "Use third party CA certificates". Accepting the browser's certificate warning instead may work without the install, and the device log's `secure` count says whether it did.
2. Open `https://<laptop-ip>:4173/?canvas=<id>&devicelog=1`, write for a minute, then compare `input.pen` in `data/logs/device.jsonl`: `samples` well above `moves`, and `secure: 1`. Judge by eye whether the ink keeps up with the pen.
