# 0102: Mark-up as instruction (INK-141)

Date: 2026-11-08. No migration: everything is derived from `scene_elements`, `diagrams` and `agent_ops.result_json.at`.

- **Detector `markup`** (`agent/detectors.py`, `agent/markup.py`; rule, no model call; score 0.85, action `diagram`, reason "Apply mark-up?"). For each accepted diagram, the diagram box is the union of its live elements (`<current_op>:` ids). Mark-up ink is any live element that is not agent-authored (`customData.author != "agent"`), was written at or after the diagram's Accept time (`result.at`), no later than `MARKUP_WINDOW_S` = 1800 s after it, and whose box overlaps or touches the diagram box. Any such ink raises one offer anchored on the diagram's own agent chunk (found by element-id overlap); no agent chunk, no offer. Hypotheses to tune on logs: the 30 minute window and the 0.85 score.
- **Key per writing burst.** The offer key is `<diagram>:<id of the oldest ink>`, so more strokes in the same burst add nothing and a dismissed offer stays dismissed. After a revision is accepted the diagram's Accept time moves past the old ink, so it no longer counts.
- **Shortcut: accepted diagrams only.** A still-pending draft is not covered: `edit_diagram` needs an accepted diagram (409 `diagram_not_accepted`), so the user accepts first.
- **Task mode `markup`** (`db/tasks.py`): only `draw_diagram`, limit 1; the API enforces it (`task_op_limit`, `task_mode`). `edit_diagram` is a `draw_diagram` op that carries `diagram_id`, so the existing budget check applies.
- **Crop.** `GET /documents/{doc}/diagrams/{id}/markup` (JSON: `diagram_id, version, source, source_kind, ink_ids, box`) and `.../markup.png`: `raster.render_crop` of the diagram's elements plus the ink recoloured `#D32F2F` on copies, so the agent tells old diagram from new ink. Works with either `INKBRIDGE_CROP_SOURCE` (render_crop is pure). Ink is recomputed per request with no window. Outline-only, not pixel-identical to Excalidraw; legibility is an owner check.
- **Runner.** `MODE_TOOLS["markup"]` = `read_canvas, get_region, get_markup, edit_diagram`; every other mode still denies `edit_diagram`. No vault tools. MCP `get_markup` uses `ApiClient` only (boundary unchanged).
- **No new op type.** The revision is the INK-140 op, so invariant N1 and the "user ink is never edited" tests still cover it: nothing in this ticket writes the scene, and `test_markup_end_to_end` shows the ink row byte-identical and live after Accept.
- **Old ink is excluded by id, not by time.** `updated_at` and `seq` change on every write, so a stroke nudged or recolured after Accept would look new. At Accept the server records `result.near`: the ids of live elements whose box already overlapped the new shapes. `ink_over` skips them, so touching old ink raises no offer and gives no red in the crop. Limits: old ink that was not near the diagram at Accept but is later moved onto it counts as mark-up; a diagram accepted before this change has no `near` and falls back to the time rule only. Timestamps are parsed with `datetime.fromisoformat` (all writers use `db.common._now`, but nothing relies on string order).
