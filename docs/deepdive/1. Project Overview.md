# Project Overview

## What is Inkbridge?

A handwritten canvas (Excalidraw) wired into a markdown vault. The server groups ink into addressable **chunks**. MCP agents (Claude Desktop / Claude Code) read the whole canvas, write vault notes that trace back to the ink, answer questions, and draw back as drafts the user accepts or rejects. Spec of record: v3 (23 Oct 2026); build by 27 Oct 2026, submit 28 Oct.

This folder (`docs/deepdive/`) is the code-level documentation. The product-level wiki is `docs/codewiki/` (overview, flows, API tables). Page-by-page implementation detail is in `4. Deep Dive/`.

## Core purpose

1. Keep handwriting as the source of truth while making it readable by agents.
2. Give every piece of ink a stable id and three hashes so notes can prove where each line came from and tell when it is stale.
3. Let agents add text and diagrams without ever editing the user's ink.

## Technology stack

- **Language**: Python 3.11+ (server), TypeScript (web), plus a stdlib-only Python helper for the export skill
- **Frameworks**: FastAPI + Uvicorn, SQLite (raw `sqlite3`, WAL), Pillow, httpx, MCP Python SDK 2.x, `google-genai`; React 19, Vite 8, `@excalidraw/excalidraw` 0.18, `@excalidraw/mermaid-to-excalidraw` 2.2
- **Build tools**: `uv` (server), npm (web), Make, ruff, oxlint, `tsc -b` (TypeScript ~7.0 and `@types/node` 26 on `main`)
- **Key dependencies**: Excalidraw (canvas and Mermaid conversion, browser only), Gemini Flash-Lite (opt-in recognition)
- **Tests**: pytest (34 test files in `server/tests/`), Node's built-in runner for `web/tests/*.test.ts`

## Key features (built)

- Scene storage with optimistic versioning and conflict merge
- Chunker with proximity clustering, arrow merge/link rules, stable ids, manual merge/split
- Three hashes: `stroke_hash`, `content_hash`, `text_hash`
- Recognition cache plus background worker (opt-in per canvas)
- MCP tools: `read_canvas`, `get_region`, `list_regions`, `search`, `check_sync`, `create_canvas`, `write_text`, `draw_diagram`; prompt `sketch_to_diagram`
- Agent ops queue, WebSocket push, dashed drafts
- Deep links from notes to chunks, chunk overlay
- Vault export skill with edit-safe blocks and early-cutoff re-export

## Getting started

```bash
make install        # uv sync + npm install
make dev-server     # FastAPI on :8000 (reload)
make dev-web        # Vite on :5173, --host so the tablet can reach it
make test           # server pytest + web tests
make lint           # ruff + oxlint + tsc -b
```
Open `http://<laptop>:5173/?canvas=<id>`. Register the MCP server: `claude mcp add inkbridge -- uv run --directory /path/to/inkbridge/server inkbridge-mcp`. Copy `.env.example` to `.env`; Gemini is only used for canvases listed in `INKBRIDGE_RECOGNIZE_DOCUMENTS`.

## Architecture summary

Three processes, one owner of state: the browser (Excalidraw), the FastAPI API with SQLite, and a thin MCP stdio server that is an HTTP client of the API. See [2. Architecture Overview.md](2.%20Architecture%20Overview.md).
