# Project Overview

> Snapshot written 26 Oct 2026; sections marked Updated 13 Nov 2026 were refreshed.

## What is Inkbridge?

A handwritten canvas (Excalidraw) wired into a markdown vault. The server groups ink into addressable **chunks**. MCP agents (Claude Desktop / Claude Code) read the whole canvas, write vault notes that trace back to the ink, answer questions, and draw back as drafts the user accepts or rejects. Spec of record: v3 (23 Oct 2026); built by 27 Oct 2026, submitted 28 Oct. Updated 13 Nov 2026: the v4 wave is merged and the project is at feature freeze (see `docs/codewiki/roadmap.md` and the repo `README.md`).

This folder (`docs/deepdive/`) is the code-level documentation. The product-level wiki is `docs/codewiki/` (overview, flows, API tables). Page-by-page implementation detail is in `4. Deep Dive/`.

## Core purpose

1. Keep handwriting as the source of truth while making it readable by agents.
2. Give every piece of ink a stable id and three hashes so notes can prove where each line came from and tell when it is stale.
3. Let agents add text and diagrams without ever editing the user's ink.

## Technology stack

- **Language**: Python 3.11+ (server), TypeScript (web), plus a stdlib-only Python helper for the export skill
- **Frameworks**: FastAPI + Uvicorn, SQLite (raw `sqlite3`, WAL), Pillow, networkx, httpx, MCP Python SDK 2.x, `google-genai`; React 19, Vite 8, `@excalidraw/excalidraw` 0.18, `@excalidraw/mermaid-to-excalidraw` 2.2
- **Build tools**: `uv` (server), npm (web), Make, ruff, oxlint, `tsc -b` (TypeScript ~7.0 and `@types/node` 26 on `main`)
- **Key dependencies**: Excalidraw (canvas and Mermaid conversion, browser only), Gemini Flash-Lite (opt-in recognition on test pages) or Claude Haiku through one persistent `claude -p` session (Updated 13 Nov 2026)
- **Tests**: pytest (about 100 test files in `server/tests/`, about 1,500 tests), Node's built-in runner for `web/tests/*.test.ts` (57 files)

## Key features (built; Updated 13 Nov 2026)

- Per-element scene storage with per-element merge, an IndexedDB device journal and live `scene.delta` push between devices
- Chunker v2 (default): stroke kinds, line-aware clustering, connectors, oversized-chunk split, stable ids, manual merge/split
- Three hashes: `stroke_hash`, `content_hash`, `text_hash`
- Recognition cache plus background worker (opt-in per canvas) with a Gemini or Claude Haiku reader and a diagram structure hint
- MCP tools: `read_canvas`, `get_region`, `list_regions`, `search`, `retrieve`, `check_sync`, `create_canvas`, `write_text`, `draw_diagram`, `edit_diagram`, `get_markup`, `get_subgraph`, `canvas_components`, `what_changed`, `set_canvas_brief`, `list_questions`, `answer_question`, `list_tasks`, `claim_task`, `complete_task`; prompt `sketch_to_diagram`
- Agent ops queue, WebSocket push, drafts that live in the op row and are accepted or rejected per draft, diagram objects with versions and mark-up as instruction
- Ask panel with threads, streaming answers and source chips; agent tasks and the optional `claude` runner
- Deep links from notes to chunks, chunk overlay, canvases home, app shell with tool rail and properties card
- Vault export skill with edit-safe blocks, early-cutoff re-export, vault-style notes and a learning loop
- Proactive offers are built but OFF by default (`INKBRIDGE_OFFERS`, decision 0121)
- Offline eval harness (`eval/`) with synthetic data

## Not built

Real-page evals, the demo video, a PWA, cross-out and circle gestures, multi-user, an Obsidian-native view, a local reader for offers. See `docs/codewiki/roadmap.md`.

## Getting started

```bash
make install        # uv sync + npm install
make dev-server     # FastAPI on :8000 (reload)
make dev-web        # Vite on :5173, --host so the tablet can reach it
make test           # server pytest + web tests
make lint           # ruff + oxlint + tsc -b
```
Open `http://<laptop>:5173/?canvas=<id>` (Updated 13 Nov 2026: daily use is `make serve`, which serves the built app and API on `http://<laptop>:8000/`, with `/` the canvases home; `make serve-https` for the tablet). Register the MCP server: `claude mcp add inkbridge -- uv run --directory /path/to/inkbridge/server inkbridge-mcp`. Copy `.env.example` to `.env`; Gemini is only used for canvases listed in `INKBRIDGE_RECOGNIZE_DOCUMENTS`.

## Architecture summary

Three processes, one owner of state: the browser (Excalidraw), the FastAPI API with SQLite, and a thin MCP stdio server that is an HTTP client of the API. See [2. Architecture Overview.md](2.%20Architecture%20Overview.md).
