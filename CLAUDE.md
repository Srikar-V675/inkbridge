# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Inkbridge is a handwritten canvas (Excalidraw) wired into a markdown vault. In the v3 design the server groups ink into addressable **chunks**, and MCP agents read the whole canvas, write vault notes that trace back to the ink, answer questions, and draw back as drafts the user accepts or rejects. Much of this is still planned; the architecture bullets below say which parts are built.

Spec of record: **spec v3 (final, 23 Oct 2026)** https://claude.ai/artifact/FkyFV1UySxqfC9oFEYb1P1. How it works (schema, hashes, chunker, API, flows): **technical reference v3** https://claude.ai/artifact/1uMmVHEyuvb2uS5Dgutaqy. `docs/project-doc.html` is the v1 draft, kept as history only. Work is planned as numbered tickets (`INK-xxx`) in `docs/tickets/`, which is local and gitignored; read `docs/tickets/README.md` before starting a task. Build by 27 Oct 2026, submit 28 Oct.

## Commands

```bash
make install          # uv sync (server) + npm install (web)
make dev-server       # FastAPI on :8000 (reload)
make dev-web          # Vite on :5173, --host so the tablet can reach it
make serve            # build web, then API + built app on :8000 (tablet: http://<laptop>:8000/?canvas=default)
make serve-https      # same over HTTPS on :4173 for the tablet (every pen sample needs a secure context; INK-181)
make install-skill    # symlink skills/inkbridge-export into ~/.claude/skills (every Claude session)
make test             # server pytest
make lint             # ruff + oxlint + tsc -b
```

- Write/pan lag harness (INK-174, decision [0073](docs/decisions/0073-write-pan-lag.md)): `cd web && npm run perf` (`scripts/perf/bisect.mjs`, headless Chromium under CPU throttle against a perf build from `scripts/perf/vite.perf.config.ts`, stock Excalidraw page `perf/stock.tsx`); `--guard` fails when the app is over 20% + 2 ms of stock. Not part of CI; `playwright-core` is not a dependency (the script header says how to install it for a run).
- Single server test: `cd server && uv run pytest tests/test_health.py::test_health`
- Web: `npm test` runs framework-free logic tests with Node's built-in runner (`web/tests/`, no extra dependency); other checks are `npm run lint`, `npx tsc -b`, `npm run build` (run in `web/`). The dev server proxies `/documents`, `/ops`, `/regions`, `/search`, `/health` and `/ws` to the API (`INKBRIDGE_API_URL`, default `http://127.0.0.1:8000`) because the API sends no CORS headers; the canvas is selected with `?canvas=<id>`.
- Daily use is single-origin (INK-100, decision [0057](docs/decisions/0057-single-origin-serve.md)): `make serve` (`KEEPALIVE=65` default) serves `web/dist` from the API on :8000 (`/assets` immutable, `/` no-cache, `/favicon.svg`, no SPA catch-all; `inkbridge/api/web.py`), so the tablet needs no Vite proxy. The Vite dev server on :5173 is for development only. Register the MCP server once with `claude mcp add --scope user inkbridge -- uv run --directory <repo>/server inkbridge-mcp`.
- Add dependencies only when a ticket needs them: `cd server && uv add <pkg>` or `cd web && npm install <pkg>`.
- CI (`.github/workflows/ci.yml`) runs the same lint, test and build; keep `make lint test` green before pushing.

## Architecture

Three processes, one owner of state:

```
tablet browser (web/, Excalidraw)  <-- HTTP + WebSocket -->  server/ API (FastAPI + SQLite)
                                                                   ^ HTTP only
                                                  MCP server (server/.../mcp, stdio) <-- Claude Desktop / Code
```

Code layout (INK-108; one area per folder, files kept small so tickets touch few files):

- `server/src/inkbridge/`: `api/` (FastAPI routes; `retrieve.py` serves `GET /retrieve`; `web.py` serves the built app, `debug.py` the flag-gated device-log and echo routes, `canvases.py` the canvases-home routes), `db/` (SQLite, one module per table group: `documents`, `scenes`, `elements` (one row per scene element, INK-110), `regions`, `chunks`, `ink`, `recognitions`, `crops`, `ops`, `questions`, `sync`, `outline`, `retrieve` (cross-canvas keyword search, INK-136), `migrations`; `db/__init__` re-exports them), `canvas/` (pure scene logic: `hashes`, `strokes` (stroke-kind classifier, INK-121), `thumb_focus` (thumbnail centre chunk, INK-179), `chunker/` package (v1 plus the v2 modules `lines`, `connectors`, `scene_v2`; INK-122), `graph`, `sketch*`, and `raster`, the Pillow renderer for crops and thumbnails; INK-120), `agent/` (`placement`, `mermaid`, `ask_runner`), `recognizer/` (Gemini reader and `worker`), `mcp/` (`app` holds the server and client, `tools/` one module per tool area, incl. `retrieve`, `server` is the entry point).
- `web/src/`: `app/` (`Root` picks home or one canvas; UI size S/M/L in `uiScale.ts`, `uiScaleStore.ts`, `UiSizeControl.tsx`, `uiScale.css` (INK-177); the shell: top bar, tool rail, zoom control, paper dots, save-status slot; touch routing in `touchInput.ts`, `touchRouting.ts`, `TouchLayer.tsx` and `fingerDraws.ts`; `app/props/` holds the shapes flyout and properties card: `ShapesFlyout`, `PropsCard`, `propsLogic`, `propsStore`), `home/` (canvases home), `ui/` (design-system primitives and the dev-only `Kit` page), `styles/` (`tokens.css`, `fonts.css`, `fonts/`), `sync/` (scene, crops, ops socket, startup), `chunks/` (overlay, deep links, merge/split), `drafts/` (render, resolve, pan-to-draft, draft tray and card), `ink/` (pen-sample collector `penSamples` feeding the patched Excalidraw freedraw handler, and the fast ink layer `fastInk` / `FastInk`; INK-181), `ask/` (Ask panel: list and thread views), `lib/` (route, `nav` for in-app switching, status, view, timing, dev log, `excalidrawEnv`, and the measurement set `deviceLog`, `stalls`, `probe`, `measure`). `main.tsx` stays at the root. `web/scripts/copy-fonts.mjs` copies the Excalidraw fonts into `web/public` before dev and build. `web/scripts/perf/` (bisect driver, variants, perf Vite config) and `web/perf/` (stock Excalidraw page) are the INK-174 lag harness, dev tooling only.
- A new module goes in the folder for its area; tests patch a name in the module that uses it, not in the package `__init__`.

- **The API is the single owner** of scenes, regions, recognitions and the agent write queue. The MCP server is a thin HTTP client and must never import `inkbridge.db`; a boundary test enforces it.
- **Scene** = one versioned snapshot of Excalidraw elements per document (optimistic `base_version` on PUT).
- **Region** = a set of element ids + server-computed bbox + hashes + crop PNG. Built: manual regions (`created_by='user'`, `POST /documents/{id}/regions`). **Chunks** are regions with `created_by='auto'` (decision [0004](docs/decisions/0004-chunks-replace-manual-regions.md)). Built: the pure clustering step in `canvas/chunker/` (union-find proximity, bound text joins its container, arrows/lines/drafts/deleted elements excluded, reading order, kind hint; INK-030), run inside every scene save with chunks persisted under stable ids (greedy element-id Jaccard match incl. orphaned chunks, `successor_of` on split/merge, reactivation on undo; INK-031, decision [0011](docs/decisions/0011-chunk-identity.md)); `GET /documents/{id}/regions` lists manual regions, `?chunks=true` lists chunks. Built: arrows (short ones merge their two chunks, long ones add `links` rows rebuilt on every save, the arrow and its label join the chunk of its start; INK-032, decision [0013](docs/decisions/0013-arrow-links.md)). Built: manual override as pinned chunks, not as a second region on the same elements (INK-059, `POST /documents/{id}/chunks/merge|split`, decision [0024](docs/decisions/0024-manual-chunk-override.md)). Built: the eval harness (INK-050, `eval/`, `evalkit`, `eval/run.py`, decision [0033](docs/decisions/0033-eval-harness.md)): offline experiments for chunking, staleness and transcription with a gated Gemini reader; only SYNTHETIC fixtures are committed, the real page set is pending. Built: read-only networkx graph view, `GET /documents/{id}/graph/subgraph|path|components` and MCP `get_subgraph` / `canvas_components`, built in memory per request over active chunks and arrow links (INK-060, decision [0056](docs/decisions/0056-networkx-subgraph.md)).
- **Three hashes, three jobs** (built, decision [0005](docs/decisions/0005-content-hash.md)): `stroke_hash` (exact ink, drives `png_stale`), `content_hash` (shape of the ink, ignores ids and absolute position; keys the recognition cache and search index, and later note provenance), `text_hash` (normalised reading, stored on each recognition; drives early-cutoff staleness in `check_sync`).
- **Recognition** is a cache keyed by `(region, content_hash, source)` (built); precedence `user > agent > gemini`. A changed content hash means new recognition; unchanged or merely moved ink never triggers a model call. Built: the swappable Gemini recognizer (`inkbridge.recognizer`, decision [0006](docs/decisions/0006-gemini-limits.md)). Built: crop sync (INK-057, `web/src/sync/cropSync.ts`, decision [0015](docs/decisions/0015-chunk-crop-sync.md)): only the browser can render crops, so it uploads PNGs for `png_stale` chunks when the canvas is idle and saved, one chunk per idle slot with per-chunk failure backoff and no export at all for a chunk over 4096 units or 1500 elements (INK-096, decision [0052](docs/decisions/0052-large-chunk-crop-budget.md); outlines say `read_status: too_large`), with the scene version it rendered (`PUT /regions/{id}/image` answers 409 if the scene moved on). Built: the background recognition worker (INK-014, `inkbridge/recognizer/worker.py`, decision [0017](docs/decisions/0017-recognition-worker.md)): its own thread and connection, reads fresh-crop regions with no reading for their content hash once the canvas is idle, backs off on failures; off unless `INKBRIDGE_RECOGNIZE_DOCUMENTS` lists canvases; it never reads a too-large chunk (INK-096).
- **Vault loop** *(built: INK-033..037; export skill `skills/inkbridge-export` with helper `scripts/inknote.py`, format `docs/vault-note-format.md`, decision [0021](docs/decisions/0021-vault-export-skill.md))*: the backend never writes the vault. A skill (`skills/inkbridge-export`) calls `read_canvas`, writes a note with one marker-bounded block per chunk (`<!-- ink:ID hash:H -->` ... `<!-- /ink -->`), frontmatter `inkbridge: {canvas, exported, chunks:[{id, hash, reading, section}]}` (one JSON line), a plain-URL deep link (`?canvas=&chunk=`, base from `INKBRIDGE_PUBLIC_URL`) and a folded crop preview. Built: `check_sync` (INK-036, `POST /documents/{id}/check_sync` and the MCP tool, `db/sync.py`, decision [0020](docs/decisions/0020-check-sync.md)) compares content hashes, has the recognition worker re-read changed chunks (bounded wait) and flags a section stale only if the reading changed (early cutoff). Re-export rewrites only changed blocks. Built: INK-105/106 (decisions [0062](docs/decisions/0062-deep-links-and-skill-install.md), [0063](docs/decisions/0063-skill-vault-alignment.md)): the skill finds its helper from its own directory, so `make install-skill` makes it work from any session; new notes follow the user's vault rules (`content/library/<title>.md`, vault frontmatter, `For future agent` callout, crops in `content/raw/attachments/inkbridge/`); each chunk entry carries a `body` hash, and a block the user edited gets a `[!conflict] Inkbridge` callout instead of being rewritten.
- **Ask AI is vendor-neutral** *(questions API and the pull-path MCP tools `list_questions` / `answer_question` built: INK-047, decision [0035](docs/decisions/0035-questions-pull-path.md); INK-046, the runner spike, was waived; the runner is built: INK-048, `agent/ask_runner.py`, decision [0007](docs/decisions/0007-ask-runner.md))*: the backend stores questions and history (`questions`, `parent_id` for follow-ups). Pull path: any MCP client calls `list_questions` / `answer_question`. Push path (optional): an `AgentRunner` adapter (Claude Code headless for the demo) started by `INKBRIDGE_RUNNER`. The runner accepts read-only vault tools by name (a `search|read|get|list` word anywhere in the name, no write word; INK-103, decision [0060](docs/decisions/0060-runner-vault-tools-and-errors.md)), and the runner MCP config must list the vault server too (`--strict-mcp-config`). Each question carries `runner_status` / `runner_error` (migration 0006), so a refused config or three failed attempts show in the panel. A follow-up with no selection inherits its parent's focus and the browser gets answers over the WebSocket `question.update`, with no polling (INK-104, decision [0061](docs/decisions/0061-ask-followup-focus-and-push.md)). Never depend on one vendor's session resume or channels.
- **Write-back** *(built: queue INK-041 (`api/ops.py`, `db/ops.py`, `agent/placement.py`, decision [0009](docs/decisions/0009-agent-ops-queue.md)); WebSocket push and draft rendering INK-042 (`api/ws.py`, `web/src/sync/opsSocket.ts`, `drafts/drafts.ts`, `drafts/drawOp.ts`, decision [0012](docs/decisions/0012-ws-push-and-drafts.md)). MCP `write_text` and `create_canvas` INK-043 (decision [0019](docs/decisions/0019-write-text-and-new-canvas.md)); `write_text` and `draw_diagram` text is sized from the handwriting, with a `size` argument on `write_text` (INK-066, decision [0032](docs/decisions/0032-write-text-scale.md); INK-082, decision [0045](docs/decisions/0045-agent-text-scale.md)). Accept/Reject/Accept all INK-045 (`web/src/drafts/resolve.ts`, `drafts/DraftBar.tsx`, decision [0026](docs/decisions/0026-accept-reject-order.md)); pan-to-draft INK-076 (`web/src/drafts/draftView.ts`, decision [0054]))*: an agent tool creates an op in `agent_ops` (pending, delivered, applied, accepted/rejected, failed, expired); the API pushes it over WebSocket; the client renders dashed draft elements tagged `customData {author:"agent", draft:true, op_id}`; Accept/Reject/Accept all resolves them. ## Invariants that are easy to break

These describe the target design. Items marked *(planned)* are not built yet, and some unmarked ones guard paths that do not exist yet (they apply as soon as that path is written); see `docs/tickets/README.md` and `git log` for what has merged. Do not assume code exists for them.

- **User ink is never edited or deleted by an agent path** *(enforced by the op queue, INK-041, `tests/test_ops_api.py`)*. Agent ops only add new elements. Enforce in `server/` (reject payloads referencing existing element ids, and ack ids not issued for the op: they must carry its `id_prefix`); a test must fail if the check is removed. The client is not a trusted enforcement point.
- **Hashes use allow-lists.** `stroke_hash`: `id,type,x,y,width,height,angle,points,pressures,isDeleted`. `content_hash`: `type,width,height,angle,points,pressures,text,fontSize,fontFamily` plus `x,y` as offsets from the bbox origin rounded to 0.001 px; no `id`, deleted elements dropped. Never hash `version`, `versionNonce`, `updated`, `seed`, `customData`, or the cache is invalidated by every render.
- **Drafts are not content** *(built in the chunker, INK-030; planned for the recognizer worker INK-014, export INK-037 and the op queue INK-041)*: elements with `customData.draft` are skipped by the chunker, recognizer and export until accepted. Once accepted, an op's elements (id prefix `<op_id>:`) form their own chunk with an `agent` reading and never go to Gemini (INK-078, decision [0044](docs/decisions/0044-accepted-agent-chunks.md)).
- **The backend never writes the vault** *(planned: export skill INK-037)* and stores no note text. Notes carry their own provenance (ids, content hashes, reading hashes); text outside marker blocks is never touched on re-export.
- **MCP stdio**: stdout carries protocol frames only; log to stderr. The package directory is named `mcp`, so never run scripts from inside it (it shadows the SDK).
- **Mermaid conversion only runs in the browser** (`@excalidraw/mermaid-to-excalidraw`), so `draw_diagram` completes through a client acknowledgement (bounded wait, then the op expires); flowcharts only, enforced by the API (`inkbridge/agent/mermaid.py`) *(built: INK-044)*.
- **Do not generate handwriting strokes.** Agents write text boxes, shapes, arrows and Mermaid diagrams.
- **Pressure is real**: freedraw elements carry `pressures` with `simulatePressure=false`; preserve both through load, save and restore (`restoreElements` before `initialData`).
- **Recognition must never block drawing**: it runs after an idle delay, in the background *(worker planned: INK-014)*.
- **Gemini free tier trains on content.** Send only test and eval pages, never personal notes; real notes are read by Claude. The key lives in `GEMINI_API_KEY` (env, never committed, never logged). The recognition worker only reads canvases listed in `INKBRIDGE_RECOGNIZE_DOCUMENTS`; keep personal canvases out of it.
- **No Obsidian plugin, no drawing inside the vault, no cross-canvas links** (decision of 22 Oct): Obsidian instances synced by Syncthing would conflict; the backend is the single owner of canvas state.
- **Dev-only helpers stay dev-only**: the Vite `/__log` endpoint writes `web/dev.log` and must not exist in a production build.
- LAN HTTP is not a secure context; features requiring one need a different approach, not a workaround.
- Config. Built: `INKBRIDGE_DATA_DIR`, `INKBRIDGE_DB`, `INKBRIDGE_API_URL` (MCP client and web dev proxy), `INKBRIDGE_DOCUMENT`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `INKBRIDGE_RECOGNIZE_DOCUMENTS` (canvases the recognition worker may send to Gemini; unset = off), `INKBRIDGE_RECOGNIZE_IDLE_S` (see `.env.example`). `INKBRIDGE_PUBLIC_URL` (deep-link base, default `http://localhost:8000`, the served origin; set a `.local` LAN name for the tablet; INK-033, INK-105). `INKBRIDGE_VAULT` (vault folder for the export skill; the skill asks if unset, INK-037). `INKBRIDGE_CHUNK_CONTAINMENT` (containment chunk-id matching, a fraction like 0.6; off by default, INK-072, decision [0029](docs/decisions/0029-containment-matching.md)). `INKBRIDGE_RUNNER` (optional Ask runner, `claude`; unset = pull path only), `INKBRIDGE_CLAUDE_BIN`, `INKBRIDGE_RUNNER_MCP_CONFIG`, `INKBRIDGE_RUNNER_MCP_NAME`, `INKBRIDGE_RUNNER_VAULT_TOOLS`, `INKBRIDGE_RUNNER_TIMEOUT_S` (INK-048, decision 0007; `INKBRIDGE_RUNNER_VAULT_TOOLS` are full names like `mcp__vault__obsidian_search`, INK-103). `INKBRIDGE_WEB_DIST` (built web app the API serves; default `web/dist` when it holds `index.html`; read at import, INK-100). `INKBRIDGE_CROP_SOURCE` (`browser` default, or `server`; who renders chunk crops, an invalid value warns and means `browser`, read at call time; INK-120, decision [0065](docs/decisions/0065-server-raster.md)). `INKBRIDGE_CHUNKER` (`v1` default, or `v2`; a canvas's own `chunker` setting wins; invalid value warns and means `v1`, read at call time; INK-122, decision 0081). `INKBRIDGE_DEVICE_LOG` (`1` mounts `/debug/device-log` and `/debug/echo` and writes `data/logs/device.jsonl`; absent otherwise, INK-102).
